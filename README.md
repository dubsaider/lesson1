# Занятие 1 «Рисуем кодом» — сценарий для преподавателя

**Для кого:** группа прошла интенсив по C, но про картинки и формат BMP ещё ничего не знает.

**Идея занятия.** Студенты дописывают в готовую заготовку запись пикселей в файл BMP и сразу рисуют картинки. Заголовок файла в заготовке уже заполнен. Три ловушки формата заранее **не объясняются**, они проявляются как видимые поломки:
- порядок байтов в пикселе B, G, R;
- строки идут снизу вверх;
- длина строки кратна 4 байтам.

Причину студенты ищут по симптому. Говорит преподаватель мало: короткий показ, задачи по карточке, разбор поломок, галерея.

**Инженерные приёмы занятия:**
- проверка известным ответом: размер файла, посчитанный заранее;
- диагноз по симптому вместо правки наугад, по одной причине за раз;
- сверка с эталоном байт в байт (`fc.exe /b`).

## Файлы

| Файл | Кому | Что это |
|---|---|---|
| `canvas.c` | студентам | заготовка: картинка в памяти, функции рисования, `save_bmp` без записи пикселей, проверка размера файла |
| `tasks.md` | студентам | карточка: как устроена картинка, задачи |
| `../../../module-images/test-images/test_5x3.bmp` и `README.md` рядом с ним | студентам | эталон и таблица цветов для проверки 2 |
| `canvas_solution.c` | только вам | эталонное решение: рисует все картинки занятия и Мандельброта |
| `bugs/make_bugs.c` | только вам | делает три «сломанные» картинки для разбора, в каждой одна ошибка |

Готовые картинки уже лежат в этой папке и в `bugs/`. Пересобрать их:

```
gcc -std=c17 -Wall -Wextra canvas_solution.c -o canvas_solution -lm
.\canvas_solution.exe
cd bugs
gcc -std=c17 -Wall -Wextra make_bugs.c -o make_bugs
.\make_bugs.exe
```

До пары договоритесь, куда студенты присылают картинки для галереи: чат группы или общая папка.

## Ход занятия (около 90 минут)

### 1. Крючок — 5 минут

Показать `mandelbrot.bmp`. Сказать: «Это несколько десятков строк на C без единой библиотеки: для каждого пикселя считается формула, результат записывается в файл. Сегодня вы научитесь записывать картинки и нарисуете свои». Показать флаги, мишень, Серпинского — то, что они нарисуют к концу пары.

### 2. Что такое картинка — 10 минут

Три мысли, каждую — с картинкой на экране.

1. **Картинка — сетка пикселей.** Открыть `test_5x3.bmp` в просмотрщике и увеличить до упора: видно 15 квадратиков. Координаты: x — вправо, y — **вниз**, (0, 0) — левый верхний угол. Спросить: «Какие координаты у правого нижнего пикселя?» Ответ: (4, 2).
2. **Цвет — три числа 0..255: красный, зелёный, синий.** Быстрый опрос: какой цвет (255, 255, 0)? (0, 255, 255)? (128, 128, 128)? (0, 0, 0)? Ответы: жёлтый, голубой, серый, чёрный. Можно открыть палитру Paint и показать, как меняется цвет при изменении чисел.
3. **Файл BMP = заголовок + пиксели.** Заголовок — 54 байта, «паспорт»: размер файла, ширина, высота. В заготовке он уже заполнен, подробно разберём его на другом занятии. После заголовка — пиксели по 3 байта.

Больше про формат **ничего не говорить**: ни про порядок байтов, ни про порядок строк, ни про выравнивание.

### 3. Заготовка — 5 минут

Открыть `canvas.c` на экране. Показать:
- `Pixel` и `Image`: пиксель (x, y) — это `px[y * w + x]`, строка 0 — верхняя (как массив из недели 2, только развёрнутый в одну строку);
- `set_pixel`, `fill_rect` — рисовать можно сразу;
- `save_bmp`: заголовок записан, а на месте пикселей — комментарий «ваша часть»;
- `check_file`: после запуска печатает, сколько байт обещает заголовок и сколько записано на самом деле.

Запустить заготовку как есть: `header says 70 bytes, file has 54 bytes - MISMATCH`. «Пикселей ещё нет — вот проверка и сработала».

### 4. Дописывают save_bmp — 15 минут

Задача — проверка 1 из карточки. Попросить **сначала посчитать на бумаге**, сколько байт должно получиться. Многие насчитают 54 + 4 × 3 = 66.

Первая версия почти у всех будет такой: строки сверху вниз, байты R, G, B, без выравнивания. Программа напечатает `header says 70 bytes, file has 66 bytes - MISMATCH`. Это нормально и даже хорошо: не подсказывать, а спросить, откуда разница в 4 байта и что в заготовке написано про `stride`. Кто догадался дописывать нули до кратного 4, получает `OK`.

Кто сразу откроет флаг или градиент, увидит кашу: все ошибки наложатся друг на друга. Сказать: «Запомните, как выглядит, — через несколько минут разберём по одной».

### 5. Детектив: что сломано — 10 минут

Открывать по одной `bugs/bug1.bmp`, `bug2.bmp`, `bug3.bmp`. В каждой — ровно **одна** ошибка. Для каждой спросить: «Что не так? Какая строчка `save_bmp` могла это сделать?» Сначала собрать гипотезы, потом ответить.

| Файл | Что видно | Причина |
|---|---|---|
| `bug1.bmp` | флаг России, но вместо синей полосы коричневая, вместо красной синяя | байты пикселя записаны как R, G, B. В BMP порядок **B, G, R** |
| `bug2.bmp` | получился флаг Сербии: красный сверху, белый снизу | строки записаны сверху вниз. В BMP первой идёт **нижняя** строка |
| `bug3.bmp` | вместо круга наклонённый полосатый эллипс | в строке 150 × 3 = 450 байт, а длина строки в файле должна быть **кратна 4**: 452. Без двух нулевых байтов каждая следующая строка съезжает |

После третьей вернуться к проверке 1: в строке картинки 2 x 2 — 6 байт, с выравниванием 8, значит, файл 54 + 8 × 2 = **70** байт. «Маленькая картинка с известным ответом поймала ту же ошибку, которую на флаге видно только как перекос».

Правило из карточки: исправлять **по одной** причине и перезапускать.

### 6. Сверка с эталоном — 5 минут

Проверка 2: нарисовать пиксели по таблице из `test-images/README.md` и сравнить с `test_5x3.bmp` через `fc.exe /b` (в PowerShell обязательно с `.exe`). «Совпало байт в байт — значит, `save_bmp` верна, и дальше её можно не подозревать».

### 7. Рисуем — 30 минут

Задачи с карточки по порядку. Готовые картинки присылают для галереи. Кто сделал всё, переходит к ★.

Что спросить у застрявших:
- шахматы: «Какой номер клетки у пикселя x = 45? А у x = 60?» — `x / 20`, затем чётность суммы номеров по x и y;
- мишень: «Как далеко пиксель от центра? В каком он кольце?» — `(int)(d / 20)`;
- градиент: «Какого цвета углы?» Верхний левый чёрный, верхний правый красный, нижний левый синий, нижний правый пурпурный.

### 8. Галерея — 10 минут

Показать на экране 4–6 картинок, лучше разных: красивую, смешную, сломанную. Автор говорит одно: на какую ошибку наступил и как её нашёл. Закончить так: «Сегодня мы не угадывали, а проверяли: посчитали размер заранее, сравнили с эталоном, по симптому нашли строчку. Ровно так же проверяют код, который написала нейросеть».

## Ожидаемые файлы

Если у студента размер другой, ошибка в выравнивании. Заголовок в заготовке правильный, а `check_file` сразу покажет `MISMATCH`.

| Картинка | Размер | Длина строки (выравнивание) | Размер файла |
|---|---|---|---|
| проверка 1 | 2 x 2 | 8 (2 байта) | 70 |
| проверка 2 | 5 x 3 | 16 (1 байт) | 102 |
| флаг России | 101 x 60 | 304 (1 байт) | 18 294 |
| флаг Японии | 150 x 100 | 452 (2 байта) | 45 254 |
| градиент | 256 x 256 | 768 (0) | 196 662 |
| шахматы | 160 x 160 | 480 (0) | 76 854 |
| мишень | 201 x 201 | 604 (1 байт) | 121 458 |
| Серпинский | 256 x 256 | 768 (0) | 196 662 |

У градиента, шахмат и Серпинского ширина кратна 4, поэтому ошибку выравнивания они **не покажут**. На них хорошо видны две другие ошибки: перевёрнутый градиент с перепутанными цветами углов.

## Как проверено

- Обе программы и заготовка собраны в Docker (Alpine, gcc 15.2, `-std=c17 -Wall -Wextra -pedantic`) без предупреждений.
- Все картинки открыты и просмотрены: выглядят так, как описано выше.
- `my_5x3.bmp` из эталонного решения побайтово совпадает с `test_5x3.bmp`.
- `check_file` проверен на трёх вариантах `save_bmp`:
  - пустая заготовка: 54 байта при обещанных 70, `MISMATCH`;
  - наивная запись без выравнивания: 66 при 70, `MISMATCH`;
  - правильная запись: 70, `OK`.
- Как выглядит наивная первая версия (все три ошибки сразу), проверено: флаг России превращается в полосы, круг — в наклонённый эллипс.
